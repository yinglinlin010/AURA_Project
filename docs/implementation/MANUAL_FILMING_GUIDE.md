# AURA 手動拍攝操作

入口：`http://127.0.0.1:5178/?scenario=premium-journey&control=1&manual=1`。

這個入口只有五個情境控制按鈕，每個按鈕有中文用途說明，並依 Core 回報顯示下一步。AUTO PLAY、定時接受/恢復及控制頁的乘員操作捷徑不在此入口。既有工程控制入口仍保留。

## 拍攝順序

1. 控制頁：重設。回到正常行駛，清除上輪行程與觀測紀錄。
2. 控制頁：駕駛負荷高。模擬駕駛忙碌，等待頁面確認高負荷。
3. 智慧車窗：點東湖，再點加入行程。只是提案；Core 回 DEFER，中控不顯示同意。
4. 控制頁：駕駛負荷正常。讓 Core 評估安全時機並 ASK，不代表同意。
5. 中控：駕駛按接受。此時才更新共享行程。維持路線則不加入。
6. 控制頁：雲端離線。模擬雲端能力不可用，本地行程保留。
7. 後座：VIP 按靜謐模式。降低後座與車窗資訊密度。
8. 控制頁：雲端恢復。能力恢復，但 Quiet 保留、資訊 HELD。
9. 後座：VIP 按恢復資訊。此時才讓資訊重新呈現。

每一步可自行停留，等待實際画面/提示確認後再前進。拍摄时使用独立 Production HMI，控制页放另一窗口，不纳入五屏画面。record=1 只是清洁单屏呈现，不会启动录影。

控制頁的狀態證據是收到 Core 狀態後的觀測快照（kind=observed-state），不是自動送出的指令或偽造真人操作時間。Journey 及 Rear 決策保留各自實際 trace，無對應決策 ID 的環境觀測不借用其他決策冒充。HELD 本身不能證明雲端曾離線，故完成提示須有本輪實際離線與靜謐觀測。

三次獨立五屏按鍵流程驗證通過；ASK 與 HELD 各停留 5.2 秒，確認沒有定時接受、定時恢復。三輪均有九個 Core 觀測階段與非空 Gateway 事件。12 個手動引導/playback 測試及 frontend build 通過。

證據：artifacts/manual-filming/verification.json、gateway-events.json、tests.tap、build.log。此輪沒有錄製影片。

本輪只修改 Director、手動引導 helper 與驗證程式，沒有修改 CoreRuntime、Gateway、PACT 或五屏呈現。工作區目前另有新增的媒體/空調等模擬操作；它們不是東湖拍攝主線，也不代表真實車輛控制。車況、負荷、景點與雲端資料仍為明確標示的模擬。
